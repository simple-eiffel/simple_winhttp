Overview

simple_winhttp is an HTTP/HTTPS client on WinHTTP - the stack that is part of every supported Windows. Nothing to redistribute (unlike libcurl, which ships only inside an EiffelStudio installation), HTTPS through SChannel, the system certificate store for free. One synchronous exchange per call; every network condition comes back as a result object, never an exception.

Promoted from the field-proven WinHTTP glue in simple_ocr_capture and extended with HTTPS, request headers, per-call timeouts and bounded bodies. Part of the simple_* ecosystem of focused, single-purpose Eiffel libraries.

Quick Start

Installation

<library name="simple_winhttp" location="$SIMPLE_EIFFEL/simple_winhttp/simple_winhttp.ecf"/>

No external_library entry needed: the C layer links winhttp.lib via #pragma comment.

Basic Usage

local
    client: SIMPLE_WINHTTP
    headers: HASH_TABLE [STRING_8, STRING_8]
    response: SIMPLE_WINHTTP_RESPONSE
do
    create client.make

    -- One GET
    response := client.get ("https://example.org/health")
    if response.is_success then
        print (response.body)
    elseif response.is_exchanged then
        print ("HTTP " + response.status.out)
    else
        print (response.error)   -- refused, timed out, TLS failure ...
    end

    -- One POST with headers and a per-call timeout
    create headers.make (1)
    headers.put ("application/json", "Content-Type")
    response := client.send ("POST", url, headers, body_json, 40)
end

Features

Failures Are Results

Refused, timed out, TLS failure, oversized body: a response object with error text, never an exception

Redirects Never Followed

WINHTTP_OPTION_REDIRECT_POLICY_NEVER on every session: a 3xx is the reply, Location surfaced, bearer headers never re-sent

HTTPS by SChannel

Certificate validation on by default; explicit opt-out for lab rigs with self-signed certificates

Bounded Bodies

16 MiB default ceiling enforced in the read loop - a hostile reply is a clean failure, not a memory bomb

Long-Poll Ready

Separate connect and receive timeouts; the per-call receive timeout comfortably outlives a 25-30 s hold

SCOOP Safe

No shared state anywhere: handles live inside one C call, status travels by out-parameters - one instance per processor

Never Stalls the Collector

Every network-waiting external is marked blocking (0.1.1), so a long request never stops ISE's garbage collector - and never freezes another processor at its next allocation
